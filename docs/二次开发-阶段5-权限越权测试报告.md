## 2. 方案安全要求核查

| 方案要求 | 状态 | 落实情况 |
|---|---|---|
| 服务端统一校验权限，不依赖前端隐藏 | ✅ | 所有业务接口经 GroupMembershipService 在 Service 层校验，越权统一 403 |
| 检索/问答/引用路径权限过滤 | ✅ | 问答强制 groupId + 成员校验（阶段 4 权限题 0 泄漏佐证） |
| 上传文件类型与大小检查 | ✅ | `DocumentUploadService`：MAX_FILE_SIZE=256MB、扩展名白名单与长度校验（MAX_FILE_EXT_LENGTH=16）、文件名长度 255、哈希长度 128 |
| 敏感配置不入库 | ✅ | `application-local.yml`（含 DB 密码、DashScope Key）已被 gitignore，仓库无真实密钥 |
| 关键管理操作审计日志 | ✅ | `@OperationLog` 注解覆盖全部 Controller（含删除文档、成员管理、问答），LogAop 统一记录 |
| 提示词注入防护 | ⚠️ 部分 | 文档内容作为证据拼入提示词，系统提示词要求基于证据回答；建议后续在 ETL 阶段对文档内容做指令清洗（列入阶段 8 候选） |

## 4. 后续建议

1. **提示词注入清洗**：文档内容在进入证据前剥离疑似指令片段（"忽略之前的指令"等模式）；
2. 下载接口可增加短时效签名 URL，避免 token 明文传递；
3. 将 `test_authz.py` 纳入 CI，每次发版前强制回归（阶段 7 Docker 部署后可自动化）。
