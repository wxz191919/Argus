# ETL 可靠性设计

本文档说明 Argus 文档 ETL（提取-转换-加载）流水线的可靠性设计。

## 任务状态机

文档处理任务包含五个状态：PENDING（待处理）、PROCESSING（处理中）、READY（就绪）、FAILED（失败）、DELETED（已删除）。状态流转必须通过 CAS 条件更新保证原子性。

## 重试策略

ETL 失败后采用指数退避重试策略：首次重试等待 2 秒，之后每次翻倍，即 2 秒、4 秒、8 秒，最多重试 3 次。全部重试失败后文档标记为 FAILED 并记录失败原因。

## 去重机制

上传环节使用文件的 SHA-256 哈希值做秒传判断：同一群组内如果已存在相同哈希的文档，则跳过物理上传直接关联已有文档。

## 僵尸回收

服务启动时执行一次全量僵尸回收，将遗留的 PROCESSING 文档标记为 FAILED。运行期间由定时调度器每 5 分钟执行一次超时回收，只回收超过 30 分钟无进展的文档，避免误伤正常处理中的任务。

## 中间产物清理

每次重新处理文档前，必须先清理上一次处理的中间产物，包括 MySQL 中的 chunk 行、pgvector 中的向量和 Elasticsearch 中的索引文档，防止旧数据残留导致检索结果重复。
